# StudySeq / 知序 产品设计文档

## 1. 产品概述

StudySeq / 知序 是一款本地优先、离线优先的桌面端学习内容管理工具。它不是日历、不是通用待办、也不是纯笔记软件，而是围绕“学习内容”来组织学习过程：

- 用户先建立一个学习内容
- 学习内容下面承载资料、笔记和阅读
- 主页负责展示当前学习内容和进度
- 详情页负责管理资料和笔记
- 阅读页负责实际打开 PDF、Word、视频等学习内容，并在同一界面里处理笔记

这个产品的核心不是让用户“记更多东西”，而是让用户更清楚地知道：

- 我在学什么
- 我学到哪了
- 接下来该看什么
- 我的资料和笔记在哪里

## 2. 产品定位

### 2.1 目标用户

StudySeq 面向通用学习者，覆盖三类常见场景：

- 自学型用户
- 备考型用户
- 技能提升型用户

### 2.2 产品目标

产品主要解决两个问题：

- 把学习内容组织清楚
- 把学习进度看清楚

这意味着产品不追求功能堆叠，而追求让学习过程变得可见、可追踪、可持续推进。

### 2.3 产品边界

第一版本不包含：

- 账号系统
- 云同步
- 以日历为中心的布局
- 通用待办系统
- 重型仪表盘
- 大量统计图表

第一版本重点只围绕：

- 学习内容
- 进度
- 资料
- 笔记
- 阅读

## 3. 核心概念

### 3.1 学习内容

“学习内容”是系统里的上层对象，可以表示：

- 一门大主题，例如 ROS2、Python、机器学习
- 一个学习项目，例如 某考试计划、某阶段技能提升计划

学习内容是首页列表里的最小组织单位，也是用户进入详情页后的主对象。

### 3.2 资料

资料是学习内容下的主要内容资产，支持：

- 文件夹
- PDF
- 视频
- Word
- Excel

资料页的视觉语义更接近资源管理器，而不是卡片式知识库。

### 3.3 笔记

笔记属于学习内容下的辅助组织单元：

- 一个学习内容可以有多个笔记
- 笔记默认平铺展示
- 笔记可以分组，但不是强制层级

### 3.4 阅读

阅读是“打开资料/笔记之后”的工作状态。它不是单独的内容库，而是承载阅读和笔记协同的界面层。

阅读页支持：

- 左侧主内容区
- 右侧笔记区
- 笔记下拉选择
- 悬浮笔记
- 内嵌笔记
- 可拖动分栏

## 4. 数据模型

### 4.1 学习内容字段

主页层级的学习内容最小字段如下：

- 名称
- 状态
- 截止日期
- 预计工时
- 进度

### 4.2 状态枚举

学习内容状态使用以下值：

- 计划中
- 进行中
- 暂停
- 完成
- 超期

### 4.3 进度规则

第一版本中，进度由用户手动填写百分比，不做自动检测。

原因：

- 不拆学习节点时，自动计算会缺少足够可靠的输入
- 手动进度最轻量，最符合 v1 的简洁方向
- 未来如果需要，可以再扩展为自动汇总模式

### 4.4 详情页数据

学习内容详情页中，主要数据结构可以理解为：

- 学习内容
  - 资料
    - 文件夹
    - 文件
  - 笔记
    - 笔记项
    - 可选分组

### 4.5 阅读页数据

阅读页中，数据可以理解为：

- 当前打开的学习内容
- 当前打开的资料文件
- 当前选择的笔记
- 可选的悬浮笔记实例

## 5. 信息架构

### 5.1 主页

主页只做一件事：展示当前学习内容列表和进度。

主页不做：

- 左侧大导航
- 复杂摘要面板
- 日历
- 筛选器

主页内容优先级：

1. 学习内容列表
2. 学习内容状态
3. 进度
4. 预计工时
5. 截止日期

默认排序：

- 最近更新

支持排序：

- 按用户需求排序

但第一版不加筛选。

### 5.2 学习内容详情页

详情页分为两块：

- 学习资料
- 笔记

学习资料使用资源管理器式大图标布局，强调文件夹和文件的识别。

笔记区使用平铺列表，并允许后续扩展为分组。

### 5.3 阅读页

阅读页是“打开内容以后”的工作场景，结构为：

- 左侧主内容区
- 右侧笔记区
- 笔记选择下拉入口

阅读页的目标是让用户能在同一界面里完成：

- 阅读资料
- 看目录
- 切换笔记
- 记录笔记

## 6. 页面设计

### 6.1 主页设计

主页采用单栏列表布局，不保留左侧学习内容导航列。

主页内容结构：

- 顶部标题区
- 右上角操作按钮：新建、搜索
- 学习内容卡片列表

每个学习内容卡片显示：

- 名称
- 状态
- 进度
- 预计工时
- 截止日期

视觉方向：

- 浅天蓝背景
- 云感渐变
- 少边框
- 卡片轻浮起
- 整体安静、清晰、偏空气感

主页原型参考：

- [homeConcept.html](</G:/PRJ/计划软件Planassiant/product/design/homeConcept.html>)

### 6.2 详情页设计

详情页的重点是“资源管理器式资料区 + 笔记区”。

资料区：

- 文件夹使用黄色大图标块
- 文件使用白纸大图标块
- 图标下方显示名称
- 用图标和间距建立层级，而不是很多框线

笔记区：

- 平铺列表
- 支持后续分组
- 保持轻量，不做重度编辑器感

详情页原型参考：

- [detailConcept.html](</G:/PRJ/计划软件Planassiant/product/design/detailConcept.html>)

### 6.3 阅读页设计

阅读页是单一可拖动分栏布局，接近“左内容、右笔记”的结构。

页面布局：

- 上方是标题和操作区
- 中间是左右分栏
- 右上角提供笔记下拉选择
- 支持悬浮笔记
- 支持内嵌笔记

左侧主内容区用于：

- PDF 阅读
- Word 阅读
- 视频播放
- 内容预览

右侧笔记区用于：

- 笔记选择
- 笔记查看
- 笔记切换

悬浮笔记的作用：

- 让用户临时记录
- 不打断当前内容阅读
- 适合短时间标注

内嵌笔记的作用：

- 更稳定
- 更适合长期整理
- 默认形态可以更轻

阅读页原型参考：

- [readerConcept.html](</G:/PRJ/计划软件Planassiant/product/design/readerConcept.html>)

## 7. 视觉语言

### 7.1 整体风格

视觉方向是：

- 现代极简
- 蓝天灵感
- 安静、轻盈、偏空气感

不是：

- 传统 SaaS 管理后台
- 密集边框面板
- 重度仪表盘
- 强装饰性 UI

### 7.2 颜色策略

主色采用蓝色系，但不是强烈科技蓝，而是更接近天空和光感的蓝。

颜色感觉：

- 背景：浅天蓝到白的渐变
- 主色：克制的蓝
- 辅助色：淡蓝灰、浅云白
- 强调色：少量更深的蓝用于按钮和重点状态

### 7.3 字体策略

中文优先：

- MiSans 或更轻的现代中文字体路线

英文优先：

- Inter

字体策略的目标是：

- 减少厚重感
- 保持现代和清晰
- 不让界面显得像默认系统模板

### 7.4 组件气质

组件不是堆框线，而是靠：

- 留白
- 渐变
- 圆角
- 轻层次
- 图标语义

来表达结构。

## 8. 交互原则

### 8.1 拖动分栏

阅读页支持用户拖动分隔线，自行调整左侧内容区和右侧笔记区的宽度。

### 8.2 笔记切换

笔记通过下拉入口切换，不依赖深层页面跳转。

### 8.3 笔记形态切换

笔记支持两种状态：

- 内嵌
- 悬浮

默认尽量轻，必要时再弹出为悬浮窗。

### 8.4 轻量反馈

所有交互反馈都尽量轻，不要太戏剧化：

- 轻微高亮
- 轻微移动
- 轻微阴影变化

## 9. 版本边界

### 9.1 v1 必做

- 主页学习内容列表
- 学习内容状态
- 手动进度
- 学习内容详情页
- 资料文件夹和文件展示
- 笔记平铺展示
- 阅读页左右分栏
- 笔记下拉切换
- 内嵌/悬浮笔记的概念支持

### 9.2 v1 暂不做

- 自动识别学习进度
- 学习节点拆解
- 复杂标签系统
- 日历
- 云同步
- 账号系统
- 大规模统计图表

### 9.3 后续可扩展

后续如果产品方向需要，可以再加入：

- 学习节点
- 资料标注
- 阅读进度
- 自动汇总进度
- 学习记录
- 更复杂的笔记分组

## 10. AI 可读总结

如果把这个产品逻辑压缩成 AI 可理解的核心说明，可以这样理解：

1. 产品是一个本地优先的学习内容管理工具，不是日历和待办。
2. 主页只展示学习内容列表和手动进度。
3. 每个学习内容进入后，会看到资料和笔记。
4. 资料区像资源管理器，使用文件夹和文件图标块。
5. 笔记既可以平铺查看，也可以在阅读页里内嵌或悬浮。
6. 阅读页是学习内容真正被打开和处理的地方，左边看内容，右边看笔记。
7. 整体视觉是蓝天灵感的极简风，强调安静、轻盈、留白和清晰层级。

## 11. 当前设计结论

当前最稳定的 UI 结论是：

- 主页 = 单栏学习内容列表
- 详情页 = 资料管理 + 笔记管理
- 阅读页 = 左内容右笔记的可拖动分栏
- 笔记 = 内嵌 / 悬浮双形态

这个结构足够支撑第一版，也足够让后续 AI 或开发者读懂产品的大概逻辑。
