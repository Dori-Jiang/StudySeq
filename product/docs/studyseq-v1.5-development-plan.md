# StudySeq / 知序 V1.5 开发计划

## 文档定位

本文件记录 StudySeq / 知序 V1.5 的开发计划。

- V1.5 主题是“一键继续学习 + 轻量效率收口”。
- 本版本承接 V1.4 的“主页最近打开位置”，把“看见上次位置”推进到“直接回到上次位置”，并合并一批低风险的资料与笔记效率收口项。
- 本版本不做大功能扩张，不新增旧独立阅读页，不改变详情页作为学习工作台的主线。
- 总进度仍记录在 `product/docs/studyseq-project-progress.md`；本文件用于展开 V1.5 的版本目标、阶段计划、验收标准和风险。

## 版本目标

V1.5 目标：用户在主页看到最近打开资料后，可以通过轻量“继续”入口直接进入详情页，并在详情页内嵌阅读区打开对应资料；同时补齐当前文件夹资料定位、笔记保存反馈、删除影响提示和预览性能保护这些低风险效率项。

V1.5 成功口径：

- 主页学习内容栏在有最近打开记录时提供“继续”入口。
- 普通点击学习内容仍进入详情页，不强制自动打开最近资料。
- 点击“继续”后仍进入当前详情页 `/studies/:studyId`，不得恢复旧独立阅读页。
- 详情页根据继续意图自动打开目标资料。
- PDF 继续复用当前页码和缩放恢复。
- 视频继续复用播放秒数恢复。
- txt / 图片可直接打开。
- 目标资料位于文件夹内时，返回资料列表后仍停留在该文件夹。
- 目标资料失效、缺失、变成文件夹或预览失败时，详情页非阻塞提示并回到正常详情页状态。
- 资料区支持当前文件夹内的文件名搜索 / 筛选 / 排序，不做全文搜索。
- 笔记保存成功或失败有轻量状态反馈，失败时不丢输入。
- 删除文件夹前更明确展示递归影响摘要。
- 图片预览和文本预览做轻量性能保护，避免大文件搬运造成明显卡顿。

## 用户价值

V1.4 让用户知道“上次看到哪里”。V1.5 让用户少一步操作，直接回到学习现场，并减少详情页内找资料、确认笔记保存状态和判断删除影响的摩擦。

用户打开主页后可以：

1. 看见某个学习内容的最近打开资料。
2. 点击“继续”。
3. 进入详情页并直接打开该资料。
4. 对 PDF / 视频恢复到上次位置附近。
5. 在当前文件夹内快速定位资料。
6. 写笔记时明确知道是否保存成功。

这仍然是轻量的工作台效率增强，不是学习统计、打卡、足迹中心或日历工作台。

## 范围

### 进入 V1.5

- 主页学习内容栏增加轻量“继续”入口，仅在 `recentOpen` 存在时显示。
- 继续入口通过 query 参数表达继续意图，推荐形态：`/studies/:studyId?continue=1&materialId=<id>`。
- 详情页加载学习内容后，按 `materialId` 查找资料并自动打开一次。
- 自动打开资料时复用现有 `previewMaterialFile`、`getMaterialReadingState`、PDF 状态保存和视频播放状态保存链路。
- 自动打开文件夹内资料前，将资料区当前文件夹设置为该资料所在文件夹。
- 自动打开失败时只给轻提示，不弹阻断弹窗，不白屏。
- 当前文件夹内资料搜索 / 筛选 / 排序：只基于 `LearningDetail.materials` 前端派生，不做资料正文全文搜索，不新增 SQLite 表。
- 笔记保存状态提示：保存成功显示轻量“已保存 HH:MM”，保存失败保留输入并提示。
- 删除文件夹影响摘要优化：标记或确认删除文件夹前，更清楚说明包含的文件和子文件夹数量。
- 图片预览 asset URL 化 / 文本大小保护：减少大图 base64 搬运；文本过大时给明确提示或保护策略。
- 补充前端测试、真实 App 手测清单和版本文档。

### V1.5 安全加固候选

以下两项来自安全审查，和“一键继续学习”主线相对独立。V1.5 合并效率项后，建议作为安全回归阶段的候选；若时间不足，至少进入验收与后续候选。

1. 资料库位置设置收紧：避免 `set_material_library_location` 直接信任前端传入任意路径字符串；优先考虑把目录选择和设置迁移合并到 Rust command，或只允许前端传 `DEFAULT` / 选择结果 token。
2. 删除副本失败可见化：资料或学习内容删除后，如果 App 管理副本因占用或权限无法删除，不应让用户误以为完全成功；至少在 UI 或清理入口中明确提示残留可重试。

### 不进入 V1.5

- 日历、打卡、连续学习天数、学习时长、热度图。
- 独立学习记录中心或最近足迹列表。
- PDF 全文搜索、书签、自定义目录。
- Office 预览、Office 转 PDF、Office 外部打开兜底。
- 新视频格式、字幕、倍速增强、转码。
- 资料全文搜索、PDF 文本抽取、OCR、缩略图全库扫描。
- 笔记分组、富文本、Markdown、标签、双向链接、资料笔记强绑定。
- 自动计算学习进度百分比。
- 整文件夹导入、目录同步、文件监听。
- 打开原文件、打开所在文件夹、保留原路径引用。
- 新增旧独立阅读页或恢复 `/studies/:studyId/read` 路由。
- 修改根目录 `AGENTS.md`。

### V1.5 真实 App 手测记录

当前状态（2026-06-14）：用户已完成真实 App 手测。以下两条作为观察项记录，不阻塞 V1.5：

1. 搜索功能只搜索本级资料夹内容，不能搜索更下一级文件夹内容。结论：符合 V1.5 “当前文件夹资料定位”范围；递归搜索、全局资料搜索和全文搜索继续后置。
2. 删除最近打开资料后，主页不引用已删除的失效资料，但会自动接续引用更上一次新打开的有效资料。结论：符合“主页不引用失效资料”的验收口径，属于最近打开摘要的有效记录回退行为。

V1.5 安全审查后续候选：

1. 资料库位置设置仍接受前端传入路径字符串；repository 已做路径安全限制，非 V1.5 阻塞，但 V1.6 建议把“选择目录 + 设置资料库”合并到 Rust command，或使用一次性选择 token。
2. `MaterialLibraryCleanupReport.failedPaths` command 响应仍包含清理失败绝对路径；当前 UI 只显示失败数量，V1.6 可改为只返回 `failedPathCount` 或脱敏相对路径。

## 设计口径

- 主页仍是单栏学习内容列表。
- “继续”是最近打开摘要的动作化，不是新增模块。
- 推荐“继续”作为独立按钮或链接，避免用户普通点击学习内容时被强制打开最近资料。
- 最近打开摘要仍只展示上次打开时间、文件名和可定位位置。
- 目标资料不可用时，详情页顶部或资料区顶部显示轻提示，例如“最近打开资料已不可用”，不使用阻断弹窗。
- 不新增右侧面板、日历、时间线、统计卡片或独立记录页。
- 资料搜索只放在详情页资料区，且只面向当前文件夹 / 当前学习内容的资料名称，不做全局搜索中心。
- 笔记保存状态是编辑器旁的轻反馈，不做复杂协作编辑或历史版本。

## 技术设计

### 路由合同

推荐使用 query 参数：

```text
/studies/:studyId?continue=1&materialId=<materialId>
```

说明：

- `continue=1` 表示这是“继续学习”意图。
- `materialId` 是主页 `recentOpen.materialId`。
- 普通 `/studies/:studyId` 保持现有行为。
- 不新增旧阅读页路由。

### 详情页状态机

```text
getLearningDetail(studyId)
-> 读取 query 中 continue/materialId
-> 在 detail.materials 中查找目标资料
-> 目标不存在：显示轻提示，停留资料列表
-> 目标是 folder：显示轻提示，停留资料列表
-> 目标是 file：setCurrentMaterialFolderId(material.parentId)
-> 调用现有 handleOpenMaterial(material)
-> previewMaterialFile + getMaterialReadingState 并行加载
-> PDF / 视频 / txt / 图片沿用现有预览组件
```

关键约束：

- query 自动打开只处理一次，避免 effect 循环。
- 自动打开不能绕过 `previewMaterialFile`。
- PDF / 视频位置恢复不新建状态表，不复制一套状态。
- 目标资料在自定义资料库位置时，仍依赖现有动态 asset scope。

### 数据库与后端

V1.5 主线预计不新增 SQLite 表，不提升 `PRAGMA user_version`。B1/B2/B3 尽量只做前端派生状态和现有 command 调用；C1 可能调整 `preview_material_file` 的返回语义，但不新增业务表。

继续复用：

- `list_learning_contents` 返回 `recentOpen`。
- `get_learning_detail` 返回详情资料列表。
- `preview_material_file` 做资料预览和文件边界校验。
- `get_material_reading_state` 恢复 PDF 页码/缩放和视频秒数。

只有进入安全加固候选时，才可能调整 command 合同或补 Rust 测试；仍应优先避免 schema 迁移。

### 资料定位与预览性能

- 当前文件夹内搜索 / 筛选 / 排序基于已加载的 `detail.materials` 派生。
- 搜索范围默认当前文件夹，不做全文检索，不读取资料正文。
- 图片预览优先走 asset URL 或等价轻量路径，减少 Rust -> 前端 base64 搬运。
- 文本预览保留多编码支持，但需要避免超大文本一次性拖慢 UI；超限时显示明确提示。
- 这些能力不能扩大 Tauri asset scope，仍只能访问当前 App 资料库目录。

### 真实 App 手测

当前状态（2026-06-14）：用户已完成真实 App 手测。以下清单由用户执行，观察项见上方记录。

1. 打开 PDF 到第 N 页并调整缩放，回主页点“继续”，确认进入详情页后直接打开同一 PDF，并恢复页码和缩放。
2. 打开视频播放到指定时间点，回主页点“继续”，确认视频恢复到上次时间点附近。
3. 打开 txt / 图片后回主页点“继续”，确认可直接打开。
4. 最近资料在二级文件夹内，点“继续”打开后返回资料列表，确认仍停留在该文件夹。
5. 删除最近打开资料后，主页不引用失效资料；如果旧链接残留，详情页不白屏、不崩溃。
6. 自定义资料库位置下，点“继续”打开 PDF / 视频 / 图片 / txt 均可用。
7. 迁回默认资料库位置后，点“继续”仍可用。
8. 当前文件夹有 30+ 个资料时，搜索中文名、英文名、扩展名，确认过滤和排序稳定。
9. 保存笔记成功后显示“已保存”状态；模拟保存失败时标题和正文不丢。
10. 删除多层文件夹前，确认文案和底部删除栏能说明文件/子文件夹影响范围。
11. 大图片预览不明显卡顿；超大文本资料有明确提示，不导致白屏。
12. 用 V1.1 / V1.2 / V1.3 / V1.4 真实库副本升级后，学习内容、资料层级、笔记、PDF 状态、视频进度、资料库位置保留。
13. 断网状态下，主页、继续入口、详情页阅读、视频播放、笔记编辑、资料管理均可用。
14. 若进入安全加固候选：占用 App 管理副本后删除资料，确认 UI 不误报完全成功；篡改 DB 的库外 `stored_path` 不被预览、统计或删除路径读取。

## 风险

### 自动打开重复触发

影响：详情页 effect 可能因状态更新反复调用预览。

建议：用 `handledMaterialIdRef` 或等价状态保证 query 继续意图只处理一次。

### 主页链接交互冲突

影响：整行 Link、编辑按钮、删除按钮和继续入口可能互相干扰。

建议：继续入口使用独立链接或按钮区域；普通点击学习内容不自动继续。

### 大 PDF / 视频加载变慢

影响：点“继续”后可能立即打开大文件，详情页初始加载变重。

建议：详情页先展示框架，再加载阅读区域；预览失败只提示，不阻断详情页。

### 文件夹上下文丢失

影响：自动打开文件夹内资料后返回列表，用户可能回到根目录。

建议：打开前设置 `currentMaterialFolderId = material.parentId`，并补测试。

### 文件安全边界被绕过

影响：前端持有 `storedPath`，如果新增入口直接 `convertFileSrc`，可能绕过后端校验。

建议：继续入口必须先走 `previewMaterialFile`；asset URL 只在预览成功后使用。

### 资料搜索范围膨胀

影响：如果从文件名过滤扩成全文搜索、PDF 抽文本或全局资料中心，会明显扩大实现和验证成本。

建议：V1.5 只做当前文件夹/当前学习内容内的资料名称搜索、类型筛选和排序。

### 笔记保存状态不准确

影响：“已保存”如果在保存真正成功前出现，会削弱用户信任。

建议：只在 command 成功后显示保存成功时间；失败保留输入并明确提示。

### 图片 / 文本预览合同变化

影响：图片从 `dataUrl` 改 asset URL 或文本增加大小保护，可能影响现有预览测试和旧数据兼容。

建议：保留旧 payload 兼容，重点手测中文路径、大图、txt 多编码和打包后的 asset 加载。

## 后续候选

以下内容有价值，但不进入 V1.5：

- 资料正文全文搜索。
- 递归搜索下级文件夹资料名称。
- 全局资料搜索中心。
- PDF 文本抽取和索引。
- OCR。
- Office 预览或 Office 转 PDF。
- 笔记分组、富文本、Markdown、标签和双向链接。
- 移动资料弹窗快速定位目标文件夹。
- 整文件夹导入、目录同步、文件监听。
- 打开原文件或打开所在文件夹。
